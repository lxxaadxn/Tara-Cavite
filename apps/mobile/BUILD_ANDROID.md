# Building the Android app (APK / AAB)

Two supported paths. Use **Option A** for anything destined for Google Play.

---

## Option A - EAS Build (recommended)

Runs on Expo build servers, so it is immune to local Windows toolchain and path issues, and it
creates and stores the Android upload keystore for you.

```bash
npm i -g eas-cli
eas login                      # your Expo account
eas build -p android --profile production
```

- Result: a signed **AAB**, downloadable from the link EAS prints and from the Expo dashboard.
- The `production` profile in `eas.json` sets `buildType: app-bundle` and `autoIncrement: true`, so
  every build raises `android.versionCode` in `app.json` automatically.
- Release env vars come from `eas.json` -> `build.production.env`. The local `.env` is gitignored,
  so an EAS build would otherwise ship with no Supabase config.

| Profile       | Output | Use for                                  |
| ------------- | ------ | ---------------------------------------- |
| `development` | APK    | Dev client on a device or emulator       |
| `preview`     | APK    | Sharing a testable APK with other people |
| `production`  | AAB    | Google Play upload                       |

Test on your own device first:

```bash
eas build -p android --profile preview
```

## Option B - Local build (Gradle)

### IMPORTANT: the project path must not contain special characters

Windows Gradle/Kotlin builds fail when the project path contains a `!`, because the Kotlin compiler
passes source paths as `file://` URIs and `!` is the URI fragment delimiter. From this repo the error
looks like:

```
e: file:///C:/Tara,%20Cavite!/node_modules/@react-native/gradle-plugin/... Unresolved reference
```

The checkout therefore cannot build Android in place. Move or clone the repo to a plain path first,
for example `C:\dev\tara-cavite`, then run the steps below from there.

### Requirements (all present on this machine)

| Tool          | Version used | Notes                                            |
| ------------- | ------------ | ------------------------------------------------ |
| JDK           | 17           | `JAVA_HOME` already points at Eclipse Adoptium 17 |
| Android SDK   | API 36       | `ANDROID_HOME` set; build-tools 36 present       |
| NDK           | 27.x         | Needed by Reanimated and other native modules    |
| CMake         | 3.22.1       | Installed with the SDK                           |

### Steps

```bash
npm install                        # from the repo root
npm run prebuild:android -w cavitour-mobile
npm run aab -w cavitour-mobile     # wraps: cd android && gradlew.bat bundleRelease
```

Other useful targets:

- `npm run apk -w cavitour-mobile` builds a release APK: `android/app/build/outputs/apk/release/app-release.apk`
- The AAB lands at: `android/app/build/outputs/bundle/release/app-release.aab`

### Signing

Release builds are signed with the upload key in `apps/mobile/credentials/` (gitignored):

- `credentials/cavitour-upload.keystore` - PKCS12 upload key, alias `cavitour-upload`
- `credentials/keystore.properties` - store/key passwords, read by Gradle

`android/app/build.gradle` was patched to load that file and to use `signingConfigs.release` for the
release build type (Expo prebuild otherwise signs release builds with the debug key, which Google
Play rejects).

`android/` is generated by prebuild and is gitignored, so a future `expo prebuild` wipes that patch.
Re-apply it, or use EAS Build (Option A) which handles signing itself.

### Release environment variables

`.env` is gitignored, so pass the Supabase values explicitly when bundling locally:

```
set EXPO_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
set EXPO_PUBLIC_SUPABASE_ANON_KEY=YOUR-ANON-KEY
npm run aab -w cavitour-mobile
```

Without them the release bundle ships with no backend config and the app cannot load data.

## Google Play upload values

| Field                | Value                                              |
| -------------------- | -------------------------------------------------- |
| Application ID | `com.taracavite` (in `app.json`) |
| Version name         | `expo.version` in `app.json`                       |
| Version code         | `expo.android.versionCode` (auto-incremented by EAS)|
| Privacy policy URL   | `https://YOUR-DOMAIN/privacy-policy`               |
| Data deletion URL    | `https://YOUR-DOMAIN/privacy-policy`               |
